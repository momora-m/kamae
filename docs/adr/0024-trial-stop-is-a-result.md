# プレイの停止理由を、プレイセッションが返す結果にする

- 状態: `accepted`
- 日付: 2026-09-26
- 言葉: [../words.md](../words.md)
- 作業: [プレイの停止理由を、プレイセッションが返す結果にする](https://github.com/momora-m/kamae/issues/84)

## なぜ

従来のプレイセッション（`TrialShouldStop`）はプレイモードを停止すべきかどうかの真偽値のみを返していたため、プレイヤーの体力が尽きて敗北したのか、すべての敵キャラクターの体力が尽きて勝利したのかを画面上で判別できなかった。終了の判定基準そのものは変えずに、停止に至った具体的な理由をプレイセッションの実行結果として呼び出し側へ伝えられるようにする。

## 決めたこと

プレイセッションの停止判定結果として、以下の 3 状態を定義する（コード上の `TrialStop`）。

- **続行（Continue）**: プレイモードを継続する。
- **プレイヤー体力枯渇（PlayerDepleted）**: プレイヤーの体力が 0 に達した。
- **敵全滅（OpponentsDepleted）**: 参加しているすべての敵キャラクターの体力が 0 に達した。

停止の判定条件自体は [0015](0015-edit-then-start-a-trial.md) から変更しない。
- 敵キャラクターが 0 体の場合は、敵全滅による停止結果は返さない（プレイヤー死亡時のみ停止）。
- 敵が 1 体以上存在し、その全滅とプレイヤーの死亡が同一フレームで同時に発生した場合は、プレイヤー側の体力枯渇を優先して返す。
- プレイ停止中、Subjects パネルに停止理由を示す一文（「プレイヤーの体力が尽きた」または「すべての敵が倒れた」）を表示する。プレイモード中や編集モード中はこのテキストを表示しない。
- 停止後に自動で初期状態へ復帰することはせず、ユーザーが明示的に復帰操作を行うまで停止画面を維持する。

## 採らないこと

専用のリザルト演出画面、勝敗スコア集計、ラウンド制の導入、コンティニュー機能、効果音再生。停止理由の提示は既存の Subjects パネル内でのテキスト表示にとどめる。
