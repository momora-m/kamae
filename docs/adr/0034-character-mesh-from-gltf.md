# キャラクターを、ファイルから読んだ一つのメッシュで描く

- 状態: `accepted`
- 日付: 2026-09-30
- 言葉: [../words.md](../words.md)
- 作業: [一人のキャラクターを 3D モデルで描き、操作感を見る](https://github.com/momora-m/kamae/issues/106)

## なぜ

キャラクターの見た目は立方体で、色だけが分かれている。ヨー 0 の前は +Z だが、立方体では前後が同じに見えるため、歩きと技の操作感をこの見た目のままでは判断できない。頂点を `Renderer` のソースへ手で置くことはせず、既存の交換形式である glTF 2.0 から一つのメッシュを読む。

## 決めたこと

プレイヤーと相手は同じメッシュを、キャラクターごとの一色で描く。面ごとの色は付けない。床、壁、ヒットボックスは立方体のままで、いずれも今の `DrawLitMesh` に頂点バッファを渡して描く。新しいシェーダや描画経路は作らない。

- **形式**:
  - 形式は glTF 2.0 の `.gltf` と、同じディレクトリにある外部バッファ `.bin` 一つに決める。`.glb` は読まない。テキストの `.gltf` なら、小さいサンプルの差分を追える。
  - glTF は右手系で、上は +Y、前は +Z、右は -X である。このエンジンは左手系で、ヨー 0 の前は +Z、右は +X である。読み取りは位置と法線の X を反転し、左手系へ合わせる。反転によって三角形の表裏は、今の立方体と同じ時計回りになる。インデックスの順番は入れ替えない。
  - ノードの移動、回転、拡縮は適用しない。サンプルのノードは恒等変換であり、頂点はメッシュ自身の座標で範囲に入る。
  - 最初のメッシュの、最初のプリミティブだけを読む。描画モードは三角形（4）か、その省略だけを受け付ける。
  - 頂点属性は `POSITION` と `NORMAL` で、どちらも正規化しない FLOAT の VEC3 とする。インデックスは必須で、符号なし 8 ビット、16 ビット、32 ビットのいずれかとする。頂点は 65535 個までとする。これは `DrawLitMesh` の 16 ビットインデックスに合わせた上限である。
  - スパースなアクセサ、必須拡張、`data` URI、絶対パス、スキーム付き URI、`..` を含む参照は失敗とする。外部バッファは `.gltf` と同じディレクトリのファイル名だけを許す。テキストは 1 MiB、外部バッファは 4 MiB を超えたら失敗とする。
- **置き場所**:
  - ファイルは `assets/character.gltf` と `assets/character.bin` に置く。`assets` は、このメッシュのための新しいトップレベルディレクトリである。
  - ビルドは、シェーダと同じく、この二つのファイルを実行ファイルの隣へコピーする。起動時には、その隣の `character.gltf` を読む。
  - シーンファイルにはメッシュのパスを書かない。プレイヤーと相手でファイルを分けない。
- **向きと大きさ**:
  - 読み取ったあとのメッシュの前は +Z である。描画のワールド行列は、今どおりピッチ、ヨー、ロールと平行移動である。ヨーによって前が回る。
  - 歩行と攻撃の対象は、半辺 0.5 の立方体のままである。ヨーはこの立方体に効かない。
  - 読み取った頂点は、X と Z が -0.65 から 0.65、Y が -0.5 から 0.6 に収まらなければならない。立方体の面から、左右と前後へは 0.15、上へは 0.10 まで出てよい。下は立方体の底より出さない。足が床に埋まらないようにするためである。
  - 0.15 は、鼻と腕の前後で向きが分かり、短い技の左右 0.5 を見た目で置き換えない量である。二つの立方体が接するとき、見た目は合わせて 0.30 まで重なり得る。
- **サンプル**:
  - サンプルは、操作感を見るための一人分である。鼻は読み取り後の +Z へ出て、キャラクターの右腕は前、左腕は後ろにある。頂点は数百に満たない。
- **失敗**:
  - 開けない、読めない、上の条件に合わない、範囲を外れるときは、ウィンドウは開いたままにする。Render パネルに理由を出し、そのときはキャラクターを立方体で描く。床、壁、ヒットボックスは止まらない。

## 採らないこと

アニメーション、技ごとのポーズ、キャラクターごとの別メッシュ、マテリアルの作り込み、テクスチャ、アラガミ専用のモデル、アセットパイプライン一式は採らない。独自のメッシュ形式、glTF や JSON の読み込みライブラリ、スキン、モーフ、2 個目以降のプリミティブも採らない。
