# ヒットはプレイセッションが適用する結果である

- 状態: `accepted`
- 日付: 2026-09-26
- 言葉: [../words.md](../words.md)
- 作業: [当たりを試走が適用する結果として ADR に残す](https://github.com/momora-m/kamae/issues/69)

## なぜ

ヒットボックスとキャラクターの交差判定（衝突検出）と、それによるダメージ適用や被弾ヒットストップの設定が、攻撃処理関数の中で密結合していた。判定の検出と、その結果として起きるゲームルールの適用を分離する。

## 決めたこと

ヒット（当たり）を独立した「判定結果データ（`Hit`）」として扱う。
- ヒットボックス側は「どのキャラクターと重なったか」の検出と報告のみを行い、相手の体力や被弾フレーム数を直接書き換えない。
- 同一のヒットボックスが同一キャラクターを重複して報告しないよう、判定済みフラグの管理はヒットボックス側で行う。
- プレイセッション側のゲームループがこの結果を受け取り、実際のルール処理（体力を 1 減らし、[0020](0020-subject-frame-dt.md) に従って次のフレームから 4 フレーム間の経過時間を 0 秒に設定する）を適用する。
- 体力が 0 のキャラクターや攻撃者自身は判定対象外とする。移動によるキャラクター同士の接触ではヒット判定を発生させない。

## 採らないこと

被弾後の無敵時間、コンボ補正、ノックバック等の新規ステータス異常、画面全体のグローバルヒットストップ。
