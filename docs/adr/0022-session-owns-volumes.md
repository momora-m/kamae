# ヒットボックスはプレイセッションが持つ配列で管理する

- 状態: `accepted`
- 日付: 2026-09-26
- 言葉: [../words.md](../words.md)
- 作業: [箱を試走が持つことを ADR に残す](https://github.com/momora-m/kamae/issues/67)

## なぜ

ヒットボックスのデータ領域をキャラクター構造体の内部に個別スロットとして保持していたため、攻撃判定の寿命やワールド座標への残留といった「空間内の現象」がキャラクターの状態に引きずられ、コード上の責務が不明瞭になっていた。

## 決めたこと

ヒットボックスのライフサイクル管理をキャラクターから切り離し、プレイセッション側（`SceneState`）が保持する配列で一括管理する。

- 攻撃処理はキャラクターの個別スロットを上書きするのではなく、プレイセッションのヒットボックス配列へ新規要素を追加する。
- ヒットボックスの寿命管理（[0019](0019-attack-volume-lifetime.md)）および描画処理は、このセッション配列を参照して行う。
- 配列の最大長は現在のキャラクター上限数（4）とし、各キャラクターが同時に複数のヒットボックスを生成することはない（クールダウンが持続時間より長いため）。
- 編集モードへの復帰時、プレイ開始時、シーン読み込み時には配列をクリアする。全滅等でプレイが停止した場合でも、持続時間内のヒットボックスは消滅するまで描画を維持する。

## 採らないこと

ヒット判定結果の適用処理の切り出し（[0023](0023-hit-is-session-result.md) で決定）、寿命フレーム数の変更、可変長配列や動的メモリアロケーションの導入。
