# 神機は刃と銃を切り替え、銃は弾を消費して刃より遠くへ届く

- 状態: `accepted`
- 日付: 2026-10-02
- 言葉: [../words.md](../words.md)
- 作業: [神機は刃と銃を切り替え、撃つと弾を消費して刃より遠くへ届く](https://github.com/momora-m/kamae/issues/114)

## なぜ

刃は短い技と長い技の二種類で、どちらも届く距離は近接に収まっている。規定の初期配置では両者の間隔が 4 であり、そのヒットボックスは相手に重ならない。遠い攻撃を足すなら、刃の置き換えではなく、一つの武器が刃と銃の形態を持つ形にする。銃のために別の判定を新設すると、発生・持続・硬直と、同じ相手に一度だけのヒットが二重になる。プレイセッションが既に持つヒットボックスの寿命に乗せ、届く距離と弾だけを変える。

## 決めたこと

プレイヤーの神機は、刃と銃のどちらか一方である。開始時は刃とする。相手は刃のままで、形態の切り替えも銃も出さない。接近、間合い待ち、後退、短い技と長い技の選択は変えない。

- **形態**:
  - キャラクターは形態（`WeaponForm`）を持つ。刃は `Blade`、銃は `Gun` である。
  - プレイの開始、やり直し、編集への復帰、シーンの読み込みでは刃に戻す。シーンと開始状態には形態を書かない。
- **入力**:
  - 切り替えは R とする。押したフレームに一度だけ、刃と銃を入れ替える。押し続けても、そのあとのフレームでは切り替わらない。
  - 銃の発射は G とする。WASD、Space、F、Shift、Q、E は変えない。
  - 銃形態では Space と F を捨て、刃の技は出ない。刃形態では G を捨て、銃は出ない。
  - 同じフレームで R と技のキーが押されたときは、先に形態を切り替えてから、切り替えたあとの形態の技だけを見る。刃で R と G を押したフレームは銃を受け付ける。銃で R と Space を押したフレームは短い技、R と F は長い技である。Space と F が同時なら、今どおり F を優先する。
  - 同じフレームで E と R が押されたときは、回避だけを受け付け、形態は変えない。回避の途中に R を押したフレームは形態を変える。そのあいだの歩き、技、ガード、ジャンプは今どおり出ない。
  - ヒットストップでフレーム更新時間が 0 のフレームは、ジャンプと同じく切り替えない。クールダウンが 0 で、発生も硬直も残っていなければ、経過時間が 0 でも銃の番号は通る。
  - Q はどちらの形態でも跳ぶ。床に着いているフレームだけ、今どおり一度置く。
- **銃の技**:
  - 技テーブルへ銃の行（`kMoveGun`）を足す。前方 4.0、左右は中心から 0.5、次まで 0.5 秒とする。
  - 前方 4.0 は長い技の 2.0 より長い。ヒットボックスは半辺 0.5 の前面から伸び、共有する面だけでは重ならない。規定の間隔 4 では、銃の前面は相手の立方体を越え、長い技は届かない。左右は刃と同じ 0.5 のままにする。変えるのは届く距離だけである。
  - 発生 1 フレーム、持続 3 フレーム、硬直 1 フレーム、ダメージ 1、被弾時の 4 フレーム個別ヒットストップは刃と同じである。
  - ヒットボックスはプレイセッションの配列に出す。判定と描画は同じ区間を、今のヒットボックスと同じ色で見る。
  - クールダウンはキャラクターに一つである。形態を切り替えても、前の技の間隔が残っているあいだは新しい技は出ない。先行入力は、クールダウンの最後 0.15 秒だけ、その形態で出せる最後の技を覚える。出すフレームの形態で出せない技は捨てる。
  - 発生と硬直のあいだは歩けず、新しい技も出ない。切り替えても、受け付け済みの技は進む。ヒットボックスは、受け付けた行の届く距離で出る。
- **弾**:
  - 開始時の弾は 3 とする。1 発だと、減ったことと撃てなくなったことが同じことになる。3 発なら、減ったあとも撃てて、そのあと 0 で止まる。
  - 銃の技を受け付けたフレームに 1 減る。当たったかどうかでは減らない。空振りでも減る。
  - 弾が 0 のときは銃の技を受け付けない。ヒットボックスも出さず、クールダウンも始めない。
  - 弾を戻す手段は作らない。シーンと開始状態には弾を書かない。パネルからは変えない。ビューポートと Subjects では読むだけである。
  - プレイの開始とやり直しでは 3 に戻す。戦闘の途中の残数は覚えない。

ガードと回避は、このヒットボックスにも今の規則のまま効く。正面のガードは体力もヒットストップも当たった力も置かず、回避の 6 フレームも同様である。

## 採らないこと

捕食、弾の回復、自分より大きい相手、部位、歩くアニメーション、描画 API の変更、ECS、物理ライブラリ、アセットパイプライン。相手に銃を持たせること、弾や形態をパネルから編集すること、銃だけ発生や硬直を変えること、ヒットボックス以外の射撃判定を作ること。
