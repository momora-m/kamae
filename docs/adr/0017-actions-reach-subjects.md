# 操作は水平の歩きと攻撃になってから主体に届く

- 状態: `accepted`
- 日付: 2026-09-26
- 作業: [操作が主体に届く経路を ADR に残す](https://github.com/momora-m/kamae/issues/49)
- 追加: 相手の状態を、この歩きと攻撃する／しないの組み合わせにすることは [0018](0018-opponent-state-is-actions.md)。主体が受け取るものがその二つであることは、ここが現在の決定である。
- 追加: その操作を出すコントローラーが主体に付くことは [0021](0021-controller-attaches-to-subject.md)。主体が受け取るものがその二つであることは、ここが現在の決定である。

## 文脈

試走中、プレイヤーの歩きは `WalkCube` が WASD を読む。Space は呼び出し側がビューポート上で読み、`Attack` に渡す。相手は `ApproachAndAttack` が、今の接近の結果で `Attack` を直接呼ぶ。間隔、先行入力、初撃の待ちは [0016](0016-winnable-trial-attack.md) のままである。歩行の向きは [0004](0004-cube-walks-its-facing.md) と [0005](0005-walk-along-camera-yaw.md) のままである。

キーの読みと、主体が進む歩きと攻撃が同じ場所に混ざっている。GUI でコントローラーを着脱する話ではない。

## 決定

試走中、主体が受け取るのは水平の歩きと、攻撃する／しないだけである。

プレイヤーはその二つをキーから作る。相手は、今の接近の結果から作る。`ApproachAndAttack` の歩きと、撃つかどうかは今と同じである。

`WalkCube` と `Attack` はキーを見ない。渡された水平の歩きと、攻撃する／しないだけを見る。

ビューポートにカーソルがないとき、または文字入力がキーを取っているときは、今どおりプレイヤーへは何も届かない。

DirectX の型は [0002](0002-renderer-owns-directx.md) のまま、Renderer の外に出さない。

パッド、リバインド、ECS、コンポーネントの GUI、ヒットストップ、相手の新しい行動は含めない。間隔、先行入力、箱、残りは変えない。

## 結果

- キーを読む場所は一つである。そこがプレイヤーの水平の歩きと、攻撃する／しないを作る。
- 相手の接近は撃つかどうかを作り、同じ `Attack` に渡す。
- ビューポート外と文字入力中は、プレイヤーは歩かず、攻撃しない。
- パッド、リバインド、ECS、ヒットストップ、相手の新しい行動は増えない。数字も変わらない。
- 相手の状態は [0018](0018-opponent-state-is-actions.md) が、同じ歩きと攻撃する／しないの組み合わせとして置く。新しい `Attack` はここからは増えない。
