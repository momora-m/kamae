# 入力は歩きと攻撃になってからキャラクターに届く

- 状態: `accepted`
- 日付: 2026-09-26
- 言葉: [../words.md](../words.md)
- 作業: [操作が主体に届く経路を ADR に残す](https://github.com/momora-m/kamae/issues/49)

## なぜ

プレイヤーのキー入力読み取りと、キャラクターの移動・攻撃処理が同一箇所で密結合していた。これを解消し、入力を抽象化することで、プレイヤーも敵も同一のインターフェースで行動できるようにする。ただし、この段階ではコントローラーを着脱する GUI などの大掛かりな仕組みは作らない。

## 決めたこと

プレイモード中、各キャラクターが受け取るデータを「水平移動ベクトル」と「攻撃トリガーフラグ」の 2 つ（`SubjectActions`）に限定する。

- プレイヤーはキー入力からこのデータを生成する。
- 敵は接近 AI の計算結果からこのデータを生成する。
- 移動処理（`WalkCube`）および攻撃処理（`Attack`）はキーボードなどのハードウェア入力を直接参照せず、渡されたデータのみに従って動作する。
- ビューポートにマウスカーソルがない場合や、ImGui のテキスト入力がアクティブな場合は、プレイヤーへの入力生成を無効化する。
- DirectX 関連の型は `Renderer` の外へ出さない方針を維持する。

## 採らないこと

ゲームパッド対応、キーコンフィグ機能、汎用 ECS やコンポーネントシステム、コントローラー着脱用 GUI、ヒットストップ、敵の新規行動パターン。
