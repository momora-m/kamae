# 入力は歩きと攻撃になってからキャラクターに届く

- 状態: `accepted`
- 日付: 2026-09-26
- 言葉: [../words.md](../words.md)
- 作業: [操作が主体に届く経路を ADR に残す](https://github.com/momora-m/kamae/issues/49)

## なぜ

キーの読みと、キャラクターが進む歩きと攻撃が同じ場所に混ざっている。着脱する画面の話ではない。

## 決めたこと

プレイ中、キャラクターが受け取るのは水平の歩きと、攻撃する／しないだけである。

プレイヤーはその二つをキーから作る。相手は、今の接近の結果から作る。

`WalkCube` と `Attack` はキーを見ない。渡された水平の歩きと、攻撃する／しないだけを見る。

ビューポートにカーソルがないとき、または文字入力がキーを取っているときは、プレイヤーへは何も届かない。

DirectX の型は `Renderer` の外に出さない。

## 採らない

パッド。リバインド。エンティティとコンポーネント。着脱 GUI。ヒットストップ。相手の新しい行動。間隔と先行入力の数字の変更。
