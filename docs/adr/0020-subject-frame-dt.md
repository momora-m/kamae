# プレイ中、キャラクターごとに更新経過時間を渡す

- 状態: `accepted`
- 日付: 2026-09-26
- 言葉: [../words.md](../words.md)
- 作業: [時間の止め方を ADR に残す](https://github.com/momora-m/kamae/issues/57)。実装は [試走中の主体に、フレームの Δt を渡す](https://github.com/momora-m/kamae/issues/58)。

## なぜ

被弾時の手応え（ヒットストップ）を演出したいが、ゲーム全体の時間を停止させてしまうと攻撃を食らっていない第三者の敵まで静止してしまう。ヒットストップは被弾したキャラクター単体にかける必要がある。

## 決めたこと

プレイモード中、各キャラクターの更新処理（移動やクールダウン計算）に渡すフレーム経過時間（Delta Time）をキャラクター単位で独立して管理する。

- 通常時は、フレーム全体の経過秒をそのまま渡す。
- 攻撃を受けたキャラクターは、被弾した次のフレームから **4 フレーム間、渡される経過時間を 0 秒** とする（ヒットごとに残り 4 フレームへリセット）。
- 経過時間 0 秒のフレームでは、そのキャラクターの移動やクールダウンのカウントダウンは進まない。ただし、キー入力の読み取り自体は毎フレーム継続し、クールダウンがすでに完了している場合は経過時間 0 秒でも攻撃トリガーは通る。
- 被弾硬直の管理はキャラクターが保持する「停止残フレーム数」1 つのみとし、グローバルな時間操作や複雑なタイマーは増やさない。
- ヒットボックス自体の持続時間（[0019](0019-attack-volume-lifetime.md)）はフレーム単位で常に進み、被弾キャラクターの停止時間には影響されない。

## 採らないこと

ゲーム全体のグローバルヒットストップ、攻撃発生の溜め動作、被弾後の無敵時間、編集モードの一時停止仕様の変更。
