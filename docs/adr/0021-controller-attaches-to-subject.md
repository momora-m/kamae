# コントローラーは主体に付き、同じ操作を出す

- 状態: `accepted`
- 日付: 2026-09-26
- 作業: [コントローラーが主体に付く経路を ADR に残す](https://github.com/momora-m/kamae/issues/65)

## 文脈

[0017](0017-actions-reach-subjects.md) で、試走中の主体が受け取るのは水平の歩きと、攻撃する／しないだけである。プレイヤーはキーからそれを作る。相手は [0018](0018-opponent-state-is-actions.md) の状態から同じ組み合わせを作る。呼び出しはまだ分かれている。相手の接近は歩きと `Attack` を直接呼ぶ。試走の更新は先頭をプレイヤー、それ以外を相手として分岐する。

間隔、先行入力、初撃の待ちは [0016](0016-winnable-trial-attack.md) のままである。歩行の向きは [0004](0004-cube-walks-its-facing.md) と [0005](0005-walk-along-camera-yaw.md) のままである。主体ごとの Δt は [0020](0020-subject-frame-dt.md) のままである。

キーの読みと相手の接近が、同じ操作の出し手になっていない。GUI でコントローラーを着脱する話ではない。

## 決定

コントローラーは主体に付く。最初の二つは、プレイヤーのキーと相手の接近である。どちらも 0017 の水平の歩きと、攻撃する／しないを出す。

試走は、その操作から `WalkCube` と `Attack` を呼ぶ。相手の接近は歩きと `Attack` を直接呼ばない。`WalkCube` と `Attack` は、添字 0 を特別扱いしない。間隔と先行入力は、コントローラーが渡す値である。プレイヤーは今どおり 0.4 秒と先行入力、相手は今どおり 0.8 秒で先行入力は無い。

カメラの注視点と、全滅で試走を止める判定は、先頭の主体のままである。ここは歩きと攻撃の話ではない。

パッド、リバインド、ECS、コントローラーの GUI、新しい相手の状態、箱の並び、当たりの適用の切り出しは含めない。数字は変えない。実装は次の issue である。

## 結果

- コントローラーは主体に付く。プレイヤーのキーと相手の接近が、同じ操作を出す。
- 歩きと攻撃は、渡された操作だけを見る。添字 0 は見ない。
- 相手の接近は、歩きと `Attack` を直接呼ばない。
- カメラの注視点と全滅の判定は、先頭のままである。
- パッド、GUI、新しい状態、箱の並び、当たりの切り出しは増えない。数字も変わらない。
