# 入力は、どの技を出すかになる

- 状態: `accepted`
- 日付: 2026-09-26
- 言葉: [../words.md](../words.md)
- 作業: [入力は、どの技を出すかになる](https://github.com/momora-m/kamae/issues/86)

## なぜ

コントローラーからキャラクターへ渡される攻撃指示は単一の真偽値（フラグ）であり、技のリーチや攻撃間隔といった諸元は攻撃関数内の定数としてハードコードされていた。複数の攻撃技を使い分ける仕組みを導入する前段階として、アクション入力を「どの技の識別子（ID）を実行するか」という形式に改め、技の諸元をテーブル構造（データ定義）へ移行する。この段階では画面上のゲーム挙動は一切変更しない。

## 決めたこと

`SubjectActions` における攻撃の表現を、ブール値フラグから「技 ID（整数値）」へ改定する。

- **技テーブルの導入**:
  - 「技を出さない状態（`kMoveNone = 0`）」を定義する。
  - 従来の突き攻撃をテーブルの最初の行（`kMovePoke = 1`）として定義し、前方リーチ 1.0、左右幅 0.5、攻撃間隔 0.4 秒を保持させる。
  - 攻撃判定の発生フレーム（0F）、持続フレーム（3F）、被弾ヒットストップ（4F）は、全技共通のルールとして維持する。
- **入力生成とセッション処理の統一**:
  - プレイヤーの Space キー入力、および敵 AI の攻撃要求は、いずれも技 ID として `kMovePoke` を生成する。
  - プレイヤーの先行入力バッファ（クールダウン終了前 0.15 秒間）は、最後に押下された技 ID を保持する方式へ改定する。
  - プレイセッション側の攻撃処理関数（`Attack`）は指定された技 ID のテーブル行を参照してヒットボックスを生成し、クールダウンを設定する。
  - 敵の後退判定も、技テーブルで定義された該当行のヒットボックス寸法を参照して行う。

## 採らないこと

二つ目の技の実装、キー割り当ての追加、技ごとのダメージ差やヒットストップ差、発生・持続・硬直フレームの技別カスタマイズ。現時点で不要なパラメータの細分化は行わない。
