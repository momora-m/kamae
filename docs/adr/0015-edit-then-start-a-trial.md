# 編集モードとプレイモードを分け、名前付きの配置から始める

- 状態: `accepted`
- 日付: 2026-09-25
- 言葉: [../words.md](../words.md)
- 作業: [編集と開始を分ける](https://github.com/momora-m/kamae/issues/34)。[シーンを複数保存し、編集中に選んで読み込める](https://github.com/momora-m/kamae/issues/35)。[プレイヤー1対相手1の初期状態を定義し、攻撃の届かない位置から戻せる](https://github.com/momora-m/kamae/issues/36)。[プレイヤーか相手の全滅で試走を止め、開始状態へ戻す操作を出す](https://github.com/momora-m/kamae/issues/37)。

## なぜ

従来は起動直後から敵が即座にプレイヤーへ接近・攻撃を開始していたため、戦闘が進行している最中にエディタで配置を調整せざるを得ず、検証が困難であった。また、開幕の間合いを空けるために不自然な攻撃溜め動作を導入するのではなく、適切な初期配置から明示的に開始できるようにする。

## 決めたこと

- **編集モードとプレイモードの分離**:
  - 起動時は「編集モード」とし、ゲーム内時間は停止する。敵の移動・攻撃、プレイヤーの移動・攻撃は一切進行しない。
  - ユーザーが UI の `Start` ボタンを押下した時のみ「プレイモード」へ遷移する。
  - プレイモード中はキャラクターの座標編集 UI を非表示とし、シーン切り替え操作を無効化する。
- **開始状態の記憶と復帰**:
  - `Start` を押下した瞬間の配置（保存されていない一時的な編集内容を含む）を「開始状態（`StartLayout`）」としてメモリに記憶する。
  - プレイヤーの体力が 0 になるか、または生存する全敵キャラクターの体力が 0 になった時点でプレイモードを自動停止する（敵が 0 体のときはプレイヤー死亡時のみ停止）。
  - 自動復帰は行わず、全滅後の画面を維持する。UI の「開始状態に戻す（Return to start）」操作を押下することで、記憶した開始時の配置へ復帰し編集モードに戻る。
- **組み込み 1 対 1 初期配置**:
  - コード上に安全な規定初期状態を保持する。プレイヤー `(0, 0, 0)`、ヨー 0 度、敵 `(0, 0, 4)`、ヨー 180 度、床半辺 20。この距離では開幕に攻撃が届かない。
  - エディタの「初期状態に戻す（Reset to initial）」操作で、現在の配置をこの組み込み状態へリセットできる。
- **名前付きシーンの複数保存**:
  - シーンに任意の名前を付け、`scenes/` ディレクトリ配下に複数保存・一覧から読み込み可能とする。[0014](0014-save-arena-layout.md) の単一 `arena.txt` 自動読み込みは廃止する。

## 採らないこと

開幕の距離を空けるための攻撃溜めモーション（溜めは後回しではなく採用しない方針）、被弾無敵時間、プレイモード中のリアルタイム配置編集。

## 後続の更新
