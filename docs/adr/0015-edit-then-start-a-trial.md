# 編集モードとプレイモードを分け、名前付きの配置から始める

- 状態: `accepted`
- 日付: 2026-09-25
- 言葉: [../words.md](../words.md)
- 作業: [編集と開始を分ける](https://github.com/momora-m/kamae/issues/34)。[シーンを複数保存し、編集中に選んで読み込める](https://github.com/momora-m/kamae/issues/35)。[プレイヤー1対相手1の初期状態を定義し、攻撃の届かない位置から戻せる](https://github.com/momora-m/kamae/issues/36)。[プレイヤーか相手の全滅で試走を止め、開始状態へ戻す操作を出す](https://github.com/momora-m/kamae/issues/37)。

## なぜ

配置を直しているあいだも相手が歩き、攻撃していた。開幕の間合いは、攻撃の溜めで空けない。初期の位置だけで、攻撃のヒットボックスが届かないところからプレイを始める。

## 決めたこと

編集モードとプレイモードは別である。起動したときは編集モード。編集中は時間を止める。相手は歩かず、攻撃しない。プレイヤーの歩行と攻撃も進めない。パネルでの配置の変更は時間ではない。プレイは、ユーザーが開始を明示したときだけ始まる。プレイ中はシーンを切り替えない。プレイ中に配置を編集する操作は出さない。

開始したとき、そのとき編集している配置を開始状態として覚える。保存していない変更も、開始を押したときの配置なら開始状態に入る。開始状態はシーンの配置であり、戦闘の途中経過ではない。開始したときの各キャラクターの残りは 3、クールダウンは 0。

プレイヤーの残りが尽きたとき、プレイを止める。使っている相手が 1 人以上いて、その全員の残りが尽きたときも止める。相手が 0 人のときは、相手の全滅では止めない。止めたあとは、自動では開始状態に戻さない。尽きたあとの画面を残す。戻す操作で開始状態の配置に戻し、編集モードに戻る。プレイは自動では再開しない。

組み込みの初期状態を、保存したシーンとは別にコードで持つ。プレイヤー 1 人と相手 1 人。プレイヤーは `(0, 0, 0)`、ヨー 0 度、色 `(0.78, 0.48, 0.27)`。相手は `(0, 0, 4)`、ヨー 180 度、色 `(0.25, 0.42, 0.68)`。床の半辺は 20。この二点では、前方 1.0、左右は中心から 0.5 のヒットボックスは届かない。攻撃の溜めは入れない。間合いはこの初期位置だけで空ける。

初期状態に戻す操作は、編集中に、今の配置をこの 1 対 1 で置き換える。床の半辺も 20 に戻す。保存してあるシーンは消さない。保存したシーンが、この組み込みの初期状態を上書きすることはない。プレイ中にはこの操作を出さない。

シーンは名前を付けて複数保存できる。編集中に一覧から一つ選んで読み込む。読み込んだシーンが、次の開始状態になる。一つのシーンが持つデータは、[0014](0014-save-arena-layout.md) と同じ種類である。作業ディレクトリの `scenes` に置く。相手は 0 人から 3 人まで。壊れた行、範囲外の数、キャラクターが 0 人または 5 人以上のときは読み込まず、今の配置を保ち、失敗を出す。

`arena.txt` 一つへ上書きする保存と、起動時にそのファイルを読んで配置を置き換え、プレイを始めることは、ここが置き換える。既にある `arena.txt` は消さない。起動時には読まない。

## 採らない

攻撃の溜め。無敵時間。コンボ。プレイ中の編集。溜めは後に回すのではなく、採らない。

## あとから

相手とプレイヤーが同じ 0.4 秒間隔で攻撃することは [0016](0016-winnable-trial-attack.md) が置き換えた。編集モードとプレイモード、開始状態、溜めを採らないことは、ここから変えていない。

[0012](0012-edit-subject-pose.md) の、ヨーをドラッグしている相手は接近がヨーを置き換えない、という判断は残っている。プレイ中は配置の編集を出さないので、二つの判断は同時には起きない。
