# 相手の状態は、歩きと攻撃する／しないの組み合わせである

- 状態: `accepted`
- 日付: 2026-09-26
- 言葉: [../words.md](../words.md)
- 作業: [相手の状態を ADR に残す](https://github.com/momora-m/kamae/issues/53)

## なぜ

敵の行動パターン（接近して攻撃する以外）を拡張するにあたり、攻撃関数そのものを個別に増やすのではなく、キャラクターへの入力データ（移動と攻撃トリガー）の組み合わせとして整理する。

## 決めたこと

敵のステートマシンが生成する出力は、[0017](0017-actions-reach-subjects.md) で定義した「水平移動」と「攻撃トリガー」の組み合わせとする。敵専用の攻撃処理は新設せず、プレイヤーと同一の `Attack` 処理を呼び出す。

初期実装として以下の 3 状態を定義する：
1. **接近（Approach）**: プレイヤーの座標へ向かって移動する。攻撃は行わない。
2. **間合い待ち（WaitInRange）**: 移動を停止する。初撃の待機時間を進める。攻撃は行わない。
3. **攻撃（Attack）**: 移動を停止し、攻撃トリガーを立てて `Attack` を実行する。攻撃間隔の管理は `Attack` 側に委ねる。

「回り込み」や「後退」などの挙動は別個の状態とするのではなく、移動ベクトルの向きのバリエーションとして扱う（現時点では実装しない）。

## 採らないこと

攻撃の溜め動作、無敵時間、ECS 構造、コントローラー設定 GUI、ヒットボックス寿命の変更、時間の停止処理。
